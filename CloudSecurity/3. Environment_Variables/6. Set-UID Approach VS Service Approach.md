#### (a) Set-UID Approach

```
Normal User Process
        ↓  (환경변수 포함 - 사용자가 조작 가능!)
  Environment Variables  ← ⚠️ 신뢰 불가
        ↓
  Privileged Process (root 권한으로 실행)
```

- 사용자가 만든 환경변수가 그대로 Privileged Process에 전달됨
- **환경변수를 신뢰할 수 없음** → 공격 표면 큼

---

#### (b) Service Approach

```
Privileged Process (OS가 독립적으로 실행)
        ↑  Request for service (요청만 전달)
  Normal User Process
```

- Privileged Process가 **OS에 의해 독립 실행** → 사용자 환경변수와 분리됨
- **환경변수를 신뢰할 수 있음** → 공격 표면 작음
- 예시: 리눅스 데몬(daemon), 윈도우 서비스

---

#### 비교 정리

|          | Set-UID Approach | Service Approach |
| -------- | ---------------- | ---------------- |
| 권한 획득 방식 | Set-UID 프로그램 실행  | 권한 서비스에 요청       |
| 환경변수 신뢰  | ❌ 신뢰 불가          | ✅ 신뢰 가능          |
| 공격 표면    | **큼** ⚠️         | **작음** ✅         |
| 사용 예     | sudo, passwd     | 데몬, 서비스          |

**→ 그래서 Android는 Set-UID / Set-GID 메커니즘을 아예 제거했습니다.**

환경변수를 통한 공격 4가지
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
① Dynamic Linker  → LD_PRELOAD로 라이브러리 함수 교체
② External Program → PATH 조작으로 가짜 명령어 실행
③ Library          → NLSPATH 등 조작으로 번역 메시지 오염
④ Application Code → PWD 등 조작으로 Buffer Overflow 유발
