# 1. 전체 큰 그림

프로그램이 시작되기 전, 커널이 새 프로세스를 만들고 실행 파일을 올릴 때  
`main()`에 넘겨줄 정보들을 **스택(stack)** 에 미리 넣어둔다.

그 정보가 크게 4덩어리다.

1. 실제 문자열들  
   - 환경변수 문자열  
   - argv 문자열  
  
2. envp[]  
   - 환경변수 문자열들을 가리키는 포인터 배열  
  
3. argv[]  
   - 인자 문자열들을 가리키는 포인터 배열  
  
4. main() 스택 프레임 쪽  
   - argc  
   - argv 포인터  
   - envp 포인터

그림의 ① ② ③ ④가 바로 이 네 부분이다.

---

# 2. ① 문자열 영역

첫 번째 그림의 ①은 실제 문자열이 저장되는 곳이다.

예를 들어 프로그램을 이렇게 실행했다고 해보자.

./a.out hello

그리고 환경변수에 이런 값이 있다고 하자.

USER=seed  
SHELL=/bin/bash  
PATH=/usr/bin:/bin

그러면 ① 영역에는 대략 이런 문자열들이 들어간다.

"USER=seed"  
"SHELL=/bin/bash"  
"PATH=/usr/bin:/bin"  
"./a.out"  
"hello"

중요한 점은:

- ①에는 **진짜 문자 데이터**가 있다
- `envp`나 `argv`는 문자열 자체를 저장하는 게 아니라
- **여기 있는 문자열의 주소만 가리킨다**

즉 ①은 “실제 내용 저장소”다.

---

# 3. ② envp 배열

그림의 ②는 환경변수 포인터 배열이다.

즉 이런 형태라고 보면 된다.

char *envp[] = {  
    "USER=seed",  
    "SHELL=/bin/bash",  
    "PATH=/usr/bin:/bin",  
    NULL  
};

하지만 이건 개념적으로 쓴 거고, 실제로는 문자열이 ② 안에 직접 있는 게 아니라  
**②의 각 칸이 ①의 문자열 주소를 들고 있다.**

예를 들면 이런 느낌이다.

envp[0] -> ①의 "USER=seed"  
envp[1] -> ①의 "SHELL=/bin/bash"  
envp[2] -> ①의 "PATH=/usr/bin:/bin"  
envp[3] -> NULL

여기서 `NULL`이 중요한 이유는  
환경변수 개수가 따로 저장되지 않기 때문에,  
배열의 끝을 `NULL`로 표시해서 어디까지가 유효한지 알게 하는 것이다.

그래서 코드에서 이렇게 순회할 수 있다.

int i = 0;  
while (envp[i] != NULL) {  
    printf("%s\n", envp[i]);  
    i++;  
}

---

# 4. ③ argv 배열

그림의 ③은 프로그램 실행 인자 배열이다.

예를 들어 실행이

./a.out hello

였다면 대략 이렇게 된다.

char *argv[] = {  
    "./a.out",  
    "hello",  
    NULL  
};

이것도 마찬가지로 문자열 자체가 ③에 있는 게 아니라  
③의 각 요소가 ①에 저장된 인자 문자열을 가리킨다.

즉:

argv[0] -> ①의 "./a.out"  
argv[1] -> ①의 "hello"  
argv[2] -> NULL

그래서 `argv`와 `envp`는 구조가 거의 같다.

- 둘 다 포인터 배열
- 둘 다 실제 문자열은 ①에 있음
- 둘 다 끝은 `NULL`

---

# 5. ④ main() 쪽 스택 프레임

그림의 ④는 `main()`이 실행될 때 사용하는 쪽이다.

여기에 개념적으로 다음 값들이 연결된다.

int main(int argc, char *argv[], char *envp[])

즉:

- `argc` : 인자 개수
- `argv` : ③의 시작 주소
- `envp` : ②의 시작 주소

그림 아래에 있는

envp (a pointer)  
argv (a pointer)  
argc (an int)

이게 바로 그 뜻이다.

즉 `main()` 입장에서는:

- `argv`가 ③ 배열을 가리키고
- `envp`가 ② 배열을 가리킨다

# 8. 두 번째 그림: envp와 environ의 관계

이 그림이 더 중요하다.

핵심 문장은 이거다.

Both envp and environ points to the same place initially.

즉 처음에는:

- `main`의 세 번째 인자인 `envp`
- 전역 변수 `environ`

이 둘이 **같은 환경변수 배열(②)** 을 가리킨다.

개념적으로는 이런 느낌이다.

extern char **environ;  
  
int main(int argc, char *argv[], char *envp[]) {  
    // 시작 직후엔 보통  
    envp == environ  
}

정확히 말하면 “배열 내용이 같음”이 아니라  
**같은 시작 주소를 가리킨다**고 이해하면 된다.

---

# 9. envp와 environ 차이

## envp

- `main()` 안에서만 직접 받는 인자
- 지역적으로 접근
- 초기 시작 시 전달된 환경변수 배열 기준

## environ

- 전역 변수
- 프로그램 전체 어디서든 접근 가능
- libc가 관리하는 현재 환경변수 집합을 가리킴

그래서 실무적으로는 `environ`이 더 유연하다.

---

# 10. 왜 environ만 바뀌고 envp는 안 바뀌나

이게 두 번째 그림의 핵심이다.

문장:

When changes are made to the environment variables ... the location for storing the environment variables may be moved to the heap, so environ will change (envp does not change)

뜻은 이거다.

처음에는 환경변수들이 스택에 있었는데,  
프로그램이 실행 중에 환경변수를 추가/수정하면  
기존 스택 공간만으로 처리하기 어렵거나 libc가 재구성해야 해서  
새로운 공간을 **heap**에 잡을 수 있다.

예를 들어:

setenv("NEWVAR", "123", 1);

이런 걸 호출하면 libc가 내부적으로:

1. heap에 새 환경변수 문자열 공간 마련
2. heap에 새 포인터 배열 마련
3. 기존 환경변수들 + 새 변수까지 포함해서 재배치
4. 전역 `environ`을 새 배열 주소로 갱신

이런 식으로 처리할 수 있다.

그런데 `envp`는 `main()` 호출 당시 전달된 포인터라서  
자동으로 갱신되지 않는다.

즉:

처음:  
envp ----\  
          > 스택의 환경변수 배열  
environ -/  
  
변경 후:  
envp ------> 여전히 예전 스택 배열  
environ ---> 새 heap 배열

그래서 두 번째 그림에 네가 적어둔 메모처럼  
“1번 공간이 부족하면 heap으로 갈 수도 있음, 그래서 envp는 계속 예전 걸 가리키고 environ만 사용”  
이 해석이 맞다.

---

# 11. 왜 이게 중요한가

왜냐하면 환경변수를 읽을 때

- `envp`는 “초기 snapshot”에 가깝고
- `environ`은 “현재 상태”에 더 가깝기 때문이다

예를 들어 프로그램 중간에 `setenv`, `putenv`, `unsetenv` 같은 걸 쓰면  
그 이후의 최신 상태는 `environ` 쪽에서 보는 게 맞다.

그래서 강의 슬라이드에서도 `environ`을 더 reliable하다고 한 거다.

---

# 12. 예시로 보면 더 쉬움

초기 실행:

extern char **environ;  
  
int main(int argc, char *argv[], char *envp[]) {  
    printf("%p\n", envp);  
    printf("%p\n", environ);  
}

처음엔 둘이 같을 가능성이 높다.

그다음 환경변수 추가:

setenv("AAA", "aaa", 1);

이후에는:

- `environ`은 새 메모리 위치로 바뀔 수 있음
- `envp`는 원래 주소 그대로

즉 둘이 달라질 수 있다.
