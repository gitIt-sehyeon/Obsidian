# 1. 전체 큰 그림

프로그램이 시작되기 전, 커널이 새 프로세스를 만들고 실행 파일을 올릴 때  
`main()`에 넘겨줄 정보들을 **스택(stack)** 에 미리 넣어둔다.

그 정보가 크게 4덩어리다.

1. 실제 문자열들  
   - 환경변수 문자열  
   - argv 문자열  
  
2. envp[]  
   - 환경변수 문자열들을 가리키는 포인터 배열  
  
3. argv[]  
   - 인자 문자열들을 가리키는 포인터 배열  
  
4. main() 스택 프레임 쪽  
   - argc  
   - argv 포인터  
   - envp 포인터

그림의 ① ② ③ ④가 바로 이 네 부분이다.

---

# 2. ① 문자열 영역

첫 번째 그림의 ①은 실제 문자열이 저장되는 곳이다.

예를 들어 프로그램을 이렇게 실행했다고 해보자.

./a.out hello

그리고 환경변수에 이런 값이 있다고 하자.

USER=seed  
SHELL=/bin/bash  
PATH=/usr/bin:/bin

그러면 ① 영역에는 대략 이런 문자열들이 들어간다.

"USER=seed"  
"SHELL=/bin/bash"  
"PATH=/usr/bin:/bin"  
"./a.out"  
"hello"

중요한 점은:

- ①에는 **진짜 문자 데이터**가 있다
- `envp`나 `argv`는 문자열 자체를 저장하는 게 아니라
- **여기 있는 문자열의 주소만 가리킨다**

즉 ①은 “실제 내용 저장소”다.

---

# 3. ② envp 배열

그림의 ②는 환경변수 포인터 배열이다.

즉 이런 형태라고 보면 된다.

char *envp[] = {  
    "USER=seed",  
    "SHELL=/bin/bash",  
    "PATH=/usr/bin:/bin",  
    NULL  
};

하지만 이건 개념적으로 쓴 거고, 실제로는 문자열이 ② 안에 직접 있는 게 아니라  
**②의 각 칸이 ①의 문자열 주소를 들고 있다.**

예를 들면 이런 느낌이다.

envp[0] -> ①의 "USER=seed"  
envp[1] -> ①의 "SHELL=/bin/bash"  
envp[2] -> ①의 "PATH=/usr/bin:/bin"  
envp[3] -> NULL

여기서 `NULL`이 중요한 이유는  
환경변수 개수가 따로 저장되지 않기 때문에,  
배열의 끝을 `NULL`로 표시해서 어디까지가 유효한지 알게 하는 것이다.

그래서 코드에서 이렇게 순회할 수 있다.

int i = 0;  
while (envp[i] != NULL) {  
    printf("%s\n", envp[i]);  
    i++;  
}

---

# 4. ③ argv 배열

그림의 ③은 프로그램 실행 인자 배열이다.

예를 들어 실행이

./a.out hello

였다면 대략 이렇게 된다.

char *argv[] = {  
    "./a.out",  
    "hello",  
    NULL  
};

이것도 마찬가지로 문자열 자체가 ③에 있는 게 아니라  
③의 각 요소가 ①에 저장된 인자 문자열을 가리킨다.

즉:

argv[0] -> ①의 "./a.out"  
argv[1] -> ①의 "hello"  
argv[2] -> NULL

그래서 `argv`와 `envp`는 구조가 거의 같다.

- 둘 다 포인터 배열
- 둘 다 실제 문자열은 ①에 있음
- 둘 다 끝은 `NULL`

---

# 5. ④ main() 쪽 스택 프레임

그림의 ④는 `main()`이 실행될 때 사용하는 쪽이다.

여기에 개념적으로 다음 값들이 연결된다.

int main(int argc, char *argv[], char *envp[])

즉:

- `argc` : 인자 개수
- `argv` : ③의 시작 주소
- `envp` : ②의 시작 주소

그림 아래에 있는

envp (a pointer)  
argv (a pointer)  
argc (an int)

이게 바로 그 뜻이다.

즉 `main()` 입장에서는:

- `argv`가 ③ 배열을 가리키고
- `envp`가 ② 배열을 가리킨다
