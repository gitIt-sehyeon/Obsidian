# Dynamic Linking (동적 링킹)

---

## 1. 개념

Dynamic Linking = 실행 시점(runtime)에 라이브러리를 연결하는 방식

- Shared Library 사용 (`.so`)
- Windows에서는 DLL

---

## 2. 전체 실행 흐름

Executable (부분 연결 상태)  
        ↓  
Loader (execve)  
        ↓  
Dynamic Linker (ld.so)  
        ↓  
main() 실행

---

## 3. 단계별 설명

### 3-1. Executable (Partially Linked)

컴파일된 실행 파일  
하지만 완전히 연결되지 않은 상태

- printf 같은 함수는 아직 주소 없음
- “나중에 연결해야 함” 상태

---

### 3-2. Loader (execve)

실행 파일을 메모리에 로드

- 코드, 데이터 메모리에 적재
- 아직 라이브러리 연결 안 됨

---

### 3-3. Dynamic Linker (핵심)

ld.so / ld-linux.so가 실행됨

역할:

1. 필요한 라이브러리 확인  
2. shared library 로드  
3. 함수 주소 연결 (예: printf)

---

### 🔥 중요

이 단계에서 환경변수가 사용됨

예:

LD_PRELOAD  
LD_LIBRARY_PATH

---

### 3-4. Jump to main()

모든 연결 완료 후 main() 실행

---

## 4. 메모리 상태 변화

초기:  
[ 실행파일 (미완성) ]  
  
링커 실행 후:  
[ 실행파일 + 라이브러리 연결 완료 ]

---

## 5. 핵심 포인트

### 5-1. 실행 파일은 처음부터 완전하지 않다

컴파일 결과 = partially linked

---

### 5-2. 실행 중 완성된다

dynamic linker가 runtime에 완성

---

### 5-3. 환경변수가 개입한다

LD_PRELOAD → 라이브러리 우선 로드  
LD_LIBRARY_PATH → 라이브러리 경로 변경

---

## 6. 공격 연결 (중요)

환경변수 조작  
        ↓  
Dynamic linker 동작 변경  
        ↓  
라이브러리 바꿔치기  
        ↓  
함수 가로채기 (Hooking)

---

## 7. 핵심 흐름 한 줄

execve → ld.so → 라이브러리 연결 → main()

---

## 8. 한 줄 정리

Dynamic Linking은 "실행하면서 프로그램을 완성하는 과정"이고,  
이 과정이 공격 지점이다
