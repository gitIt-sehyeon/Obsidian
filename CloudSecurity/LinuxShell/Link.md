# 리눅스 링크(Link) 완전 정리

## 먼저, 파일이 저장되는 구조부터

리눅스에서 파일을 저장하면 실제로는 **3가지 요소**로 나뉩니다.

```
[ 파일명 ]  →  [ inode ]  →  [ 실제 데이터 블록 ]
"hello.txt"     #1234          "안녕하세요..."
```

- **파일명** : 우리가 보는 이름
- **inode** : 파일의 정보 (크기, 권한, 데이터 위치 등)를 담은 표
- **데이터 블록** : 실제 내용이 저장된 공간

> 즉, 파일명은 그냥 "inode 번호로 가는 화살표"일 뿐입니다.

---

## 하드 링크 (Hard Link)

**같은 inode를 가리키는 화살표를 하나 더 만드는 것**입니다.

```
"hello.txt"  ──┐
               ├──▶  inode #1234  ──▶  "안녕하세요..."
"hello2.txt" ──┘
```

- `hello.txt`와 `hello2.txt`는 **완전히 동일한 파일**
- 어느 쪽을 수정해도 둘 다 바뀜
- `hello.txt`를 삭제해도 `hello2.txt`가 있으면 **데이터는 안 사라짐**
- inode에는 "나를 가리키는 화살표가 몇 개인지" 카운트가 있고, 이게 0이 되어야 실제로 삭제됨

---

## 심볼릭 링크 (Symbolic Link / Symlink)

**"저 파일로 가세요"라는 메모를 담은 별도의 파일**을 만드는 것입니다.

```
"shortcut.txt"  ──▶  inode #9999  ──▶  "/home/user/hello.txt" 라는 텍스트
                                                ↓
                                         hello.txt 찾아서 열기
                                                ↓
                                         inode #1234  ──▶  "안녕하세요..."
```

- `shortcut.txt`는 그냥 **경로가 적힌 메모 파일**
- 원본(`hello.txt`)을 삭제하면 메모가 가리키는 곳이 없어져서 **링크가 깨짐**
- 다른 디스크나 파티션에 있는 파일도 가리킬 수 있음

---

## 비유로 정리

||하드 링크|심볼릭 링크|
|---|---|---|
|비유|같은 집에 **문을 하나 더 만든 것**|집 주소가 적힌 **메모지**|
|원본 삭제 시|문이 하나 없어져도 **집은 그대로**|메모가 가리키는 집이 없어져 **길을 잃음**|
|다른 파티션|❌ 불가|✅ 가능|
|디렉토리|❌ 불가|✅ 가능|

---

## 직접 확인해보기

```bash
# 파일 만들기
echo "안녕하세요" > hello.txt

# 하드 링크 생성
ln hello.txt hard_link.txt

# 심볼릭 링크 생성
ln -s hello.txt sym_link.txt

# 확인
ls -li
```

결과를 보면:

```
1234 -rw-r--r-- 2 user user 14 hello.txt      ← inode 1234, 링크 수 2
1234 -rw-r--r-- 2 user user 14 hard_link.txt  ← inode 번호가 같음!
9999 lrwxrwxrwx 1 user user  9 sym_link.txt -> hello.txt  ← l로 시작 = 심볼릭
```

- 하드 링크는 **inode 번호가 동일**
- 심볼릭 링크는 `l`로 시작하고, `-> hello.txt`로 원본을 가리킴
