# 📌 ACID(Atomicity, Consistency, Isolation, Durability)

데이터베이스에서 **트랜잭션(Transaction)** 이란,

> 여러 개의 작업을 “하나의 논리적 단위”로 묶어서 처리하는 것  
> 예: _A 계좌 → B 계좌로 50달러 이체하기_

이때 트랜잭션이 신뢰할 수 있게 동작하도록 보장하는 네 가지 속성이 바로 **ACID**야.

---

# 1️⃣ 원자성 (Atomicity) — “모 아니면 도”

### ✔ 정의

트랜잭션 안에 있는 모든 작업이

- **전부 성공**하거나
    
- **아예 아무것도 반영되지 않아야** 한다.
    

즉, **중간까지 하고 실패하는 상태는 금지!**

### ✔ 펀드 이체 예시

A → B 로 50달러 이체 트랜잭션:

`1. read(A) 2. A = A - 50 3. write(A) 4. read(B) 5. B = B + 50 6. write(B)`

예를 들어,  
3단계까지는 완료했는데 6단계 전에 시스템이 죽으면?

- A에서 50은 이미 빠졌고
    
- B에는 50이 아직 안 들어감
    

→ 50달러가 “증발”한 것처럼 보임 → **불일치 상태**

### ✔ 그래서 필요한 것

🔄 **롤백(rollback)**  
트랜잭션 중간에 문제가 생기면,  
시작하기 이전 상태로 “완전 되돌리기” 해서 **부분 실행을 없애버림**.

---

# 2️⃣ 일관성 (Consistency) — “항상 제약 조건을 지켜야 한다”

### ✔ 정의

트랜잭션이 **성공적으로 끝나면**,  
데이터베이스는 **무결성 제약 조건을 항상 만족한 상태**가 되어야 한다.

- 기본키 중복 X
    
- 외래키 불일치 X
    
- 도메인 제약 만족
    
- 계좌 잔액 총합 무결성 만족  
    등…
    

### ✔ 펀드 이체 예시

이체 전후의 총 합:

`(이체 전)     A + B (이체 후)     (A - 50) + (B + 50)`

→ 결과는 항상 동일해야 함  
→ “돈이 갑자기 생기거나 사라지면 안 됨”

### ✔ 핵심

트랜잭션 내부에서는 잠깐 불일치해도 괜찮지만  
**끝날 때는 반드시 일관된 상태로 마무리**되어야 한다.

---

# 3️⃣ 격리성 (Isolation) — “각자 혼자 실행된 것처럼 보여야 한다”

### ✔ 정의

여러 트랜잭션이 동시에 실행되더라도  
각 트랜잭션은 **마치 자신만 실행되고 있는 것처럼** 보장받아야 한다.

즉, 다른 트랜잭션의 **중간 실행 결과를 절대 보면 안 됨**.

### ✔ 펀드 이체 예시

T1이 A→B 이체를 진행 중이고,  
A의 금액은 이미 50 빠졌는데 B는 아직 업데이트 안 됐다고 하자.

그 시점에 다른 트랜잭션 T2가 read(A), read(B)를 실행하면:

- A는 50 빠진 상태
    
- B는 아직 입금 전
    

즉, **A+B의 합이 실제보다 50 작은 값**을 보게 됨.

→ 이는 격리성이 깨진 것  
→ T2는 “비정상적인 중간 결과”를 읽은 셈

### ✔ 격리성의 의미

동시 실행되더라도:

- T2는 T1이 완료된 결과만 보도록
    
- 또는 T1이 시작되기 전 상태만 보도록
    

“직렬(serial)”로 실행한 것처럼 보이게 하는 것이 격리성.

---

# 4️⃣ 지속성 (Durability) — “커밋되면 영원히 남아야 한다”

### ✔ 정의

트랜잭션이 **커밋(commit)** 되면,  
그 결과는 **전원 꺼짐 / 시스템 오류 / DB 크래시** 등 어떤 문제가 발생해도 **절대로 사라지면 안 된다**.

### ✔ 펀드 이체 예시

A에서 50 빠지고  
B에 50 들어가는 작업이 **커밋**되었다면:

- 서버가 다운되어도
    
- 전원이 나가도
    
- 디스크 오류가 생겨도
    

이 변경 내용은 반드시 보존되도록 해야 한다.

→ 이를 위해 DB는 **로그 쓰기(Write-Ahead Logging)**, 복제(replication), 백업 등을 사용.

---

# 📌 전체 요약

|속성|핵심 의미|예시|
|---|---|---|
|**원자성**|전부 수행되거나 전혀 수행되지 않음|중간 실패 시 롤백|
|**일관성**|트랜잭션 전후로 무결성 제약 만족|A+B 총합이 항상 동일|
|**격리성**|각 트랜잭션이 독립적으로 실행된 것처럼 보임|중간 결과 읽기 방지|
|**지속성**|커밋 후 결과는 영구 보존|장애 후에도 이체 내역 유지|
