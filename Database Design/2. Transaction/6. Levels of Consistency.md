# 🚦 트랜잭션 격리 수준(Isolation Levels) — 초간단 정리

아래로 갈수록 격리 수준 높음(=성능 ↓),  
위로 갈수록 격리 수준 낮음(=겪을 수 있는 이상현상 ↑).

`Serializable        ← 가장 엄격함 Repeatable Read Read Committed Read Uncommitted    ← 가장 느슨함`

---

# 🔥 먼저 전체 개념을 한 줄로

### ✔ Read Uncommitted

→ **커밋 안 된 값도 읽음 → Dirty Read 발생**

### ✔ Read Committed

→ **커밋된 값만 읽음 → Dirty Read 방지, 하지만 Non-repeatable Read 가능**

### ✔ Repeatable Read

→ **같은 행을 여러 번 읽으면 항상 동일한 값 → Non-repeatable Read 방지, 하지만 Phantom Read는 발생**

### ✔ Serializable

→ **모든 이상 현상 방지 (직렬 스케줄처럼 동작)**

---

# 🔥 각 Isolation Level을 구체적인 예시로 이해하기

각 레벨에서 “어떤 문제”가 허용되는지 보는 게 가장 확실함.

---

# 1️⃣ Read Uncommitted (가장 낮음)

### ✔ 특징

- **커밋되지 않은(uncommitted) 값도 읽을 수 있음**
    
- Dirty Read 허용
    

### ❗ 발생 가능한 문제

#### 📌 Dirty Read

T1이 값 A=100을 50으로 바꿨지만 커밋 안 함  
→ T2가 A=50을 읽어버림  
→ 나중에 T1 실패 → rollback해서 A=100 복구  
→ T2는 존재하지 않는 값을 읽은 것!

### 🚨 이 레벨은 사실 DB에서 거의 사용 안 함 (매우 위험)

---

# 2️⃣ Read Committed (가장 많이 쓰임)

### ✔ 특징

- **커밋된 값만 읽는다.**
    
- Dirty Read 방지
    

### ❗ 여전히 발생할 수 있는 문제

#### 📌 Non-Repeatable Read

T1: A 읽음 → 100  
T2: A를 120으로 update하고 commit  
T1: 같은 A 다시 읽음 → 120

→ **같은 트랜잭션 안에서 같은 행을 두 번 읽는데 값이 달라짐!**

---

# 3️⃣ Repeatable Read

### ✔ 특징

- **커밋된 값만 읽는다**
    
- **같은 행을 여러 번 읽어도 같은 값 보장**
    

### ❗ 하지만 발생할 수 있는 문제

#### 📌 Phantom Read

T1이 “나이 < 30” 조건으로 여러 행을 SELECT  
T2가 나이 25인 새 행을 INSERT하고 commit  
T1이 다시 같은 조건으로 SELECT  
→ **행 개수가 달라짐(유령 행 등장)**

즉,

- 행의 “값”은 반복 일관하지만
    
- 행의 “집합”은 변할 수 있음
    

MySQL의 InnoDB에서는 실제로 Repeatable Read에서도 Phantom Read를 막지만,  
“이론상”으로는 Phantom이 허용되는 레벨이다.

---

# 4️⃣ Serializable (가장 높은 격리 수준)

### ✔ 특징

- 모든 트랜잭션을 **사실상 직렬화(serial execution)** 시킨 것처럼 동작
    
- 즉, 트랜잭션 간에 상호간섭이 아예 없다.
    

### ❗ 어떤 문제도 발생하지 않음

- Dirty Read ×
    
- Non-Repeatable Read ×
    
- Phantom Read ×
    

### ❗ 대가: 성능 최악

- 락이 많이 걸림
    
- 병렬성이 떨어짐
    

그래서 **현실에서는 잘 쓰지 않음 (은행 등 특수 목적 제외)**

---

# 🎯 네 가지 레벨에서 방지되는 이상현상 요약표

|이상 현상|Read Uncommitted|Read Committed|Repeatable Read|Serializable|
|---|---|---|---|---|
|Dirty Read|❗ 가능|✔ 방지|✔ 방지|✔ 방지|
|Non-Repeatable Read|❗ 가능|❗ 가능|✔ 방지|✔ 방지|
|Phantom Read|❗ 가능|❗ 가능|❗ 가능(이론적)|✔ 방지|

---

# 📌 한 번에 외우는 꿀팁

> **Dirty → Non-Repeatable → Phantom**  
> → 아래 레벨로 갈수록 더 많은 문제가 생김  
> → 위 레벨로 갈수록 더 많이 방지됨

---

# 📌 PPT 설명과 연결

### Serializable

- 가장 높은 수준 → 직렬 실행처럼 보임
    
- 가장 안전하지만 느림
    

### Repeatable read

- 같은 레코드를 반복 읽으면 변하지 않음
    
- 하지만 새로운 행(phantom)은 나타날 수 있음
    

### Read committed

- 항상 커밋된 값만 읽음
    
- 하지만 값이 계속 바뀔 수 있음
    

### Read uncommitted

- 커밋 안 된 값도 읽음
    
- 안정성 최악
