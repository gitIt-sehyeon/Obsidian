# ✅ Two-Phase Locking (2PL) Protocol — 핵심 정리

2PL(Two-Phase Locking)은 **동시성 제어(concurrency control)** 에서 가장 널리 사용되는 잠금(lock) 기반 프로토콜로,  
**모든 허용된 스케줄이 conflict-serializable이 되도록 보장하는 것**이 핵심 목표이다.

---

# 📌 1. 2PL의 목표

### ✔ **Conflict Serializability 보장**

- 트랜잭션이 동시에 실행되더라도
    
- 결과가 **어떤 순서의 직렬 실행과 동일하게 나옴**을 보장함
    

즉, **일관성(consistency) 유지**가 최우선 목표.

---

# 📌 2. 2PL의 두 단계

2PL에서는 트랜잭션이 lock을 다음 두 단계로만 획득/해제할 수 있다.

## 🔹 1) Growing Phase (성장 단계)

- lock **획득 가능**
    
- lock **해제 불가**
    
- → 잠금 수가 증가만 한다
    

## 🔹 2) Shrinking Phase (축소 단계)

- lock **해제 가능**
    
- lock **획득 불가**
    
- → 잠금 수가 감소만 한다
    

> **한 번 unlock을 수행하면 즉시 shrinking phase에 진입한다.**

---

# 📌 3. Lock Point

트랜잭션이 **마지막 lock을 획득한 시점**을 lock point라고 한다.

- 2PL 시스템에서 모든 트랜잭션은  
    **lock point 순서로 직렬화(serialization) 가능**
    
- 이것이 conflict serializability를 보장하는 근거
    

---

# 📌 4. 2PL이 보장하는 것

## ✔ Conflict Serializability

- 스케줄이 항상 conflict-serializable 하도록 보장  
    → 중간 상태를 읽는 문제(Dirty Read, Unrepeatable Read 등)를 구조적으로 억제
    

---

# 📌 5. 2PL이 보장하지 않는 것

## ❌ Deadlock 방지 불가

- 2개의 트랜잭션이 서로의 lock을 기다리는 **교착상태** 발생 가능
    
- 해결 방법: Timeout, Wait-Die, Wound-Wait, Deadlock detection 등 필요
    

## ❌ Cascading Rollback 방지 불가

- 기본 2PL에서는  
    T₂가 T₁의 uncommitted data를 읽을 수 있음
    
- T₁이 abort되면 T₂도 rollback해야 하는 **연쇄 롤백** 발생
    

---

# 📌 6. 2PL의 변형들 (문제 보완)

## 🔷 1) Strict 2PL (엄격한 2PL)

- **모든 X-lock(exclusive lock)을 commit까지 유지**
    
- S-lock(shared lock)은 조기 unlock 가능
    
- ✔ Dirty Read 및 Cascading Rollback 방지
    
- 실제 DB 대부분이 Strict 2PL을 사용
    

## 🔷 2) Rigorous 2PL (강성 2PL)

- **모든 lock(S-lock + X-lock)을 commit까지 유지**
    
- 가장 강한 형태
    
- ✔ Dirty Read 방지
    
- ✔ Cascading Rollback 방지
    
- ✔ 트랜잭션 commit 순서대로 직렬화 가능
    
- 동시성이 가장 낮지만 구현 단순 → 실무에서 흔히 "2PL"이라고 부르는 경우 이 방식을 말함
    

---

# 📌 7. Lock Conversion (잠금 변환)

트랜잭션이 이미 획득한 lock의 모드를 변환하는 기능.

### ✔ Upgrade (S → X)

- shared-lock을 exclusive-lock으로 승격
    
- **growing phase에서만 가능**
    

### ✔ Downgrade (X → S)

- exclusive-lock을 shared-lock으로 하향
    
- **shrinking phase에서만 가능**
    

---

# 📌 8. 전체 요약 (한 문장)

> **2PL은 lock을 성장 단계와 축소 단계로 구분하여 conflict serializability를 보장하는 프로토콜이며, deadlock과 cascading rollback 문제를 해결하기 위해 Strict 2PL과 Rigorous 2PL 같은 변형이 존재한다.**
