# ✅ 그래프 기반 프로토콜(Graph-Based Protocol) & 트리 프로토콜(Tree Protocol) 정리

그래프 기반 프로토콜은 **2단계 잠금(2PL)의 대안**으로 제안된 동시성 제어 방식이다.  
트랜잭션이 데이터 항목을 접근하는 순서를 **정해진 DAG(Directed Acyclic Graph) 구조**에 따라 제한함으로써 **deadlock 없이** conflict serializability를 달성하는 것이 핵심이다.

---

# 📌 1. 그래프(Partial Order) 기반 접근 규칙

- 데이터 항목 집합 D = {d₁, d₂, …, dₕ} 에 대해 **부분 순서(partial order) →** 를 정의한다.
    
- dᵢ → dⱼ 라는 의미:  
    **dᵢ와 dⱼ 둘 다 접근할 트랜잭션은 반드시 dᵢ를 먼저 접근해야 한다.**
    
- 이 규칙은 D를 **사이클 없는 방향 그래프(DAG)** 로 구성한다.  
    → 이를 **데이터베이스 그래프(database graph)** 라고 부른다.
    

---

# 📌 2. 트리 프로토콜(Tree Protocol) 규칙

그래프 기반 프로토콜의 한 종류로, **트리 구조(Tree)** 위에서 잠금을 획득하는 방식이다.

## ✔ 규칙 요약

### ① 잠금 모드:

- **오직 Exclusive(X) lock만 허용**  
    → 읽기/쓰기 모두 X-lock 필요  
    → Shared-lock 없음
    

### ② 첫 번째 잠금

- 트랜잭션 Tᵢ의 첫 lock은 **트리의 어느 노드든 가능**
    

### ③ 이후 잠금

- Tᵢ가 노드 Q를 lock하려면  
    → **Q의 parent가 이미 Tᵢ가 보유한 lock이어야 한다**  
    → 즉, 트리 경로를 따라 순서대로 잠금 획득
    

### ④ 잠금 해제

- **언제든지 unlock 가능**  
    → 2PL처럼 “Shrinking Phase” 필요 없음  
    → unlock 이후에도 나머지 잠금은 유지 가능
    

### ⑤ 재잠금 금지

- 한 번 unlock한 노드를  
    → **같은 트랜잭션이 다시 lock할 수 없음**
    

---

# 📌 3. 트리 프로토콜의 장점

### ✔ 1) Conflict Serializability 보장

- 정의된 트리 경로를 따라 lock을 획득하므로  
    **충돌 순서가 자연스럽게 직렬 가능한 구조로 강제됨.**
    

### ✔ 2) Deadlock 없음

- 경로가 항상 아래 방향으로만 진행
    
- 사이클이 존재하지 않음  
    → **순환대기(circular wait)가 불가능 → 데드락 발생 불가**
    

### ✔ 3) 더 높은 동시성

- lock을 **조기에 해제해도 됨**  
    → 2PL보다 waiting이 줄고 병렬성이 증가
    

### ✔ 4) 데드락 롤백 필요 없음

- 데드락 자체가 없기 때문에  
    데드락 해결을 위한 롤백도 발생하지 않음
    

---

# 📌 4. 트리 프로토콜의 단점

### ❌ 1) Recoverability / Cascading Rollback 보장 X

- 조기 unlock이 가능하므로  
    **uncommitted data를 다른 트랜잭션이 읽기 가능**  
    → cascading rollback 가능
    

### ❌ 2) 불필요한 잠금 획득

- 특정 노드를 접근하기 위해  
    그 **경로상의 parent들을 전부 lock해야 함**  
    → 실제로 필요하지 않은 node도 lock해야 하는 경우 발생  
    → 오버헤드 증가
    

### ❌ 3) 2PL과 스케줄 호환성 없음

- 트리 프로토콜에서는 가능한 스케줄이  
    2PL에서는 불가능할 수 있고  
    반대도 마찬가지  
    → 완전히 대체 가능한 모델이 아님  
    → 상황에 따라 장단점이 갈림
