# ✅ Deadlock Prevention (교착 상태 방지) — 정리

교착 상태 방지(deadlock prevention)는  
**트랜잭션이 아예 deadlock 상태에 들어가지 못하도록** 시스템을 설계하는 방식이다.  
다음 두 가지 대표 접근이 있다.

---

# 📌 1. 잠금 요청 순서화(Prevent Circular Wait)

이 방식은 **순환 대기(circular wait)를 원천 차단**하여 deadlock을 예방한다.

## 🔷 (1) 사전 선언(Predeclaration)

- 트랜잭션이 시작할 때  
    **필요한 모든 lock을 미리 선언**하고 한 번에 획득해야 한다.
    
- 필요한 lock 중 하나라도 획득할 수 없다면  
    → T는 기다리거나 롤백됨.
    
- 순환 대기 자체가 불가능하므로 deadlock 없음.
    

### ✔ 장점

- 데드락 완전 방지
    

### ❌ 단점

- 트랜잭션이 정확히 어떤 데이터가 필요한지  
    시작 전에 알기 어려움
    
- 높은 대기시간 + 낮은 동시성
    
- 비현실적이라 거의 사용되지 않음
    

---

## 🔷 (2) 부분 순서 부여(Partial Ordering)

- 데이터 항목 사이에 **DAG(순환 없는 방향 그래프)** 형태로 순서를 정의
    
- 예: A → B → C  
    → 어떤 트랜잭션이든 A → B → C 순서로만 lock 가능
    
- T1이 B를 잡고 A를 잡으려고 하는 상황 불가능  
    → 순환 대기 불가 → deadlock 불가
    

### ✔ 장점

- deadlock 완전 방지
    
- 비교적 단순한 규칙으로 가능
    

### ❌ 단점

- 실제 접근 경로가 tree에 따라 제한됨  
    → 불필요한 lock 획득  
    → 성능 저하 가능
    

이 방식의 대표 구현 → **트리 프로토콜(Tree Protocol)**

---

# 📌 2. 타임스탬프 기반 스킴 (Timestamp-based Deadlock Prevention)

각 트랜잭션 T에 **고유한 타임스탬프 TS(T)** 부여.  
작을수록 "오래된(older)" 트랜잭션.

> 아이디어: "older < young" 규칙을 정해서 deadlock을 막는다.

---

## 🔷 (1) Wait-Die Scheme (비선점, Non-preemptive)

### ✔ 규칙

- **Older** 트랜잭션이 young 트랜잭션이 가진 lock을 요청  
    → **기다려도 된다(wait)**
    
- **Younger** 트랜잭션이 old 트랜잭션이 가진 lock을 요청  
    → **즉시 롤백(die)**
    

### 예:

- T5(older) → T10(young): 기다림 OK
    
- T15(young) → T10(old): 롤백
    

### 특징

- 선점 없음 (다른 트랜잭션을 강제로 죽이지 않음)
    
- 롤백 횟수가 많아질 수 있음
    

---

## 🔷 (2) Wound-Wait Scheme (선점, Preemptive)

### ✔ 규칙

- **Older** 트랜잭션이 young 트랜잭션의 lock을 요청  
    → young 트랜잭션을 **강제로 롤백(wound)**  
    → old가 lock을 가져감
    
- **Younger** 트랜잭션이 old 트랜잭션 lock 요청  
    → **기다림(wait)**
    

### 예:

- T5(older) → T10(young): T10 강제 롤백
    
- T15(young) → T10(old): 기다림
    

### 특징

- 롤백 횟수가 wait-die보다 적음
    
- young을 강제 abort시킬 수 있어 처리량 증가
    

---

# 📌 3. 공통점 (Wait-die vs Wound-wait)

- 둘 다 **deadlock 자체는 절대 발생하지 않음**
    
- 하지만 **트랜잭션 롤백은 발생할 수 있음**
    
- 더 오래된 트랜잭션(older)이 우선권을 갖는다는 공통 아이디어
    
이들은 롤백된 트랜잭션이 재시작될 때 원래의 타임스탬프를 유지하도록 함으로써, 특정 트랜잭션이 영원히 잠금을 얻지 못하는 스타베이션(starvation) 문제를 방지합니다.


# 📌 4. 전체 요약 (한 문장)

> **교착 상태 방지는 “순환 대기 자체를 막거나(순서화)”,  
> “타임스탬프 기반으로 older가 우선하도록 하여 deadlock을 없애는 방식(wait-die, wound-wait)” 두 방식으로 구현된다.**
