# Multiple Granularity Locking 정리

## 📌 1. Multiple Granularity란?

데이터베이스에서 **데이터 항목의 크기(단위)** 를 여러 수준(granularity)으로 나누어 잠금을 적용하는 기법.

예:

`Database  
	└─ Area(지역)      
		└─ File(파일)          
			└─ Record(레코드)`

➡ 이렇게 “계층 구조(hierarchy)”로 표현할 수 있음  
➡ ‘큰 단위 → 작은 단위’로 내려가는 트리 구조

---

## 📌 2. Explicit Lock vs Implicit Lock

### ✔ Explicit Lock (명시적 잠금)

- 트랜잭션이 **직접 특정 노드**를 잠그는 것
    

### ✔ Implicit Lock (암묵적 잠금)

- 어떤 노드를 잠그면  
    ➜ 그 **하위 모든 노드(descendants)** 도 자동으로 **같은 모드로 잠김**
    

예:

- T₁이 **File**을 X-lock 하면  
    → 그 File 아래의 모든 **Record**도 자동으로 X-lock 상태
    

---

## 📌 3. 잠금 Granularity (잠금의 세밀함 정도)

트리에서 **어느 레벨에서 잠그느냐**가 granularity를 결정한다.

---

### ✔ Fine Granularity (작은 단위 잠금 — 아래쪽 레벨)

예: Record-level lock

- 장점: **동시성 높음** (많은 트랜잭션이 서로 간섭 없이 동시에 작업 가능)
    
- 단점: **잠금 오버헤드가 큼**  
    (lock 개수 많고 관리 비용 큼)
    

---

### ✔ Coarse Granularity (큰 단위 잠금 — 위쪽 레벨)

예: 파일 전체 lock

- 장점: **오버헤드 작음**  
    (잠금 수 적고 관리 쉬움)
    
- 단점: **동시성 낮음**  
    (한 트랜잭션이 큰 단위를 잠그면 다른 트랜잭션들이 기다림)
    

---

# ⭐ 핵심 문장 (시험/면접용)

> Multiple Granularity Locking은 데이터 항목을 계층 구조로 정의하고, 상위 노드를 잠그면 하위 노드들을 암묵적으로 잠그는 방식이다.  
> Fine granularity는 높은 동시성을 제공하지만 오버헤드가 크고,  
> Coarse granularity는 오버헤드가 적지만 동시성이 낮다.
