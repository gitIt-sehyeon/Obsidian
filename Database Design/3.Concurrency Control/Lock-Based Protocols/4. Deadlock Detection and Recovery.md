# ✅ Deadlock Detection & Recovery (교착 상태 탐지 및 복구) — 정리

Deadlock(교착 상태)은 트랜잭션들이 서로가 가진 자원을 기다리며 **영원히 진행하지 못하는 상황**을 말한다.  
Deadlock Prevention(사전 방지)과 달리, Detection & Recovery 방식은 **교착 상태가 실제로 발생할 수 있음**을 허용하고, **발생 후 탐지하여 해결**한다.

---

# 📌 1. Deadlock Detection (교착 상태 탐지)

탐지의 핵심 도구는 **Wait-for Graph(대기 그래프)** 이다.

## 🔹 대기 그래프(Wait-for Graph) 구성

### ✔ 정점(V)

- 시스템 내 모든 트랜잭션  
    예: {T₁, T₂, …, Tₙ}
    

### ✔ 간선(E)

- Tᵢ → Tⱼ  
    = 트랜잭션 Tᵢ가 Tⱼ가 보유한 lock이 풀리기를 기다리는 중  
    (= Tᵢ가 Tⱼ에 의해 block됨)
    

---

## 🔹 교착 상태 판단 기준

> ✔ **대기 그래프에 cycle(사이클)이 존재하면 deadlock 상태**

### 예:

`T1 → T2 → T3 → T1`

→ 세 트랜잭션이 서로를 기다리는 중 → deadlock

### ✔ Cycle 없음

→ deadlock 없음

---

## 🔹 탐지 주기(Detection Frequency)

- deadlock은 순간적으로 생겼다가 사라질 수 있음  
    → 주기적으로 Wait-for Graph를 검사해야 함
    
- OS 스케줄링처럼 **n초 또는 n회마다** 검사
    

---

# 📌 2. Deadlock Recovery (교착 상태 복구)

Deadlock이 탐지되면, 사이클을 깨기 위해 **한 개 이상의 트랜잭션을 롤백**해야 한다.  
롤백되는 트랜잭션을 **희생자(victim)** 라고 한다.

---

## 🔹 희생자(Victim) 선택 기준

목표: **비용(cost)** 을 최소로 하는 트랜잭션을 선택하는 것.

고려 요소:

- 지금까지 사용한 CPU 시간/자원
    
- 앞으로 남은 작업량
    
- 데이터베이스에 적용한 업데이트 양
    
- 다른 트랜잭션에 미칠 영향
    
- (중요) **과거 롤백 횟수**  
    → 여러 번 희생된 트랜잭션은 또 희생하면 안 됨
    

---

## 🔹 롤백 유형

### ✔ (1) Total rollback (전체 롤백)

- 트랜잭션을 **처음부터 완전히 재시작**
    
- 구현 간단하지만 비용 큼
    

### ✔ (2) Partial rollback (부분 롤백)

- deadlock을 깨는 데 필요한 지점까지만 롤백
    
- 이후 같은 트랜잭션이 계속 실행됨
    
- 효율적이지만 구현 복잡
    

---

# 📌 3. Starvation(기아 상태) 방지

희생자로 선택되는 트랜잭션이 계속 반복해서 롤백되면  
**아예 끝나지 못하는 기아 상태**가 발생한다.

이를 막기 위한 방법:

### ✔ 롤백 횟수를 비용 요소에 포함

- 많이 롤백된 거래는 다시 희생자로 안 뽑힘
    

### ✔ Deadlock cycle 안에서 가장 오래 실행된 트랜잭션은 절대 희생자로 선택하지 않음

- _“oldest transaction is never chosen as victim”_
    

---

# 📌 4. Prevention vs Detection 비교 요약

| 구분          | Deadlock Prevention              | Deadlock Detection & Recovery   |
| ----------- | -------------------------------- | ------------------------------- |
| Deadlock 발생 | ❌ 절대 발생 안 함                      | ✔ 발생 가능                         |
| 전략          | 발생 자체를 원천적으로 막음                  | 발생 후 찾고 해결                      |
| 수단          | Wait-die, Wound-wait, ordering 등 | Wait-for Graph, cycle detection |
| 비용          | 보수적 → 동시성 낮음                     | 롤백 비용 발생                        |
| 실무 사용       | 부분적으로 사용                         | DBMS 내부에서 널리 사용                 |

---

# ⭐ 최종 요약 (한 문장)

> **Deadlock Detection은 Wait-for Graph에서 cycle을 찾아 교착 상태를 탐지하며, cycle을 깨기 위해 비용이 가장 적은 트랜잭션을 희생자로 선정하여 완전 또는 부분 롤백으로 복구한다.**
