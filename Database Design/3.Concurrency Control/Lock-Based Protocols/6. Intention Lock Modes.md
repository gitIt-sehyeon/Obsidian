# ✅ 의도 잠금(Intention Lock) 

의도 잠금은 **Multiple Granularity Locking(다중 세분화 잠금)** 에서  
상위 노드에 “하위 노드에 어떤 잠금을 걸 예정인지” 미리 알리는 잠금 방식이다.

즉,

> **하위 레벨에 S 또는 X 잠금을 하기 위해, 상위 노드에 먼저 IS 또는 IX를 거는 구조**

그래서 잠금 체크를 효율적으로 하고, 큰 단위 잠금–작은 단위 잠금 간 충돌을 방지한다.

---

# 📌 의도 잠금 모드 종류와 의미

## ✔ IS (Intention-Shared)

- **하위 노드에 S(Shared) 잠금을 걸 예정**
    
- 즉: “나는 이 subtree 안의 일부를 읽을 거야”
    
- 상위 노드에는 IS, 하위 레코드에는 S
    

---

## ✔ IX (Intention-Exclusive)

- **하위 노드에 X (Exclusive) 잠금을 걸 예정**
    
- 즉: “나는 이 subtree 안의 일부를 수정할 거야”
    
- 상위 노드에는 IX, 하위 레코드에는 X
    

---

## ✔ SIX (Shared + Intention-Exclusive)

- 현재 노드 전체는 **S 잠금**
    
- 동시에 하위 subtree 내 일부 노드에는 **X 잠금 예정**
    
- 즉: “이 전체를 읽으면서 특정 레코드만 수정할 거야”
    

---

# 📌 왜 의도 잠금이 필요한가?

## 1) 상위 노드에서 빠른 충돌 검사 가능

레코드 하나를 잠글 때마다  
“그 위의 부모 노드들(파일, 테이블, DB)을 다 검사해야 한다면” 비용이 매우 큼.

→ 하지만 의도 잠금 덕분에  
**상위 노드만 보면 하위 노드에서 어떤 잠금을 걸었는지 알 수 있음.**

---

## 2) 큰 범위 잠금과 작은 범위 잠금 간 충돌 방지

예)

- T1이 파일 전체 S lock 걸기 원함
    
- 그런데 T2가 파일 안의 특정 record에 X lock 걸려고 하면?
    

의도 잠금 없으면 위계가 깨짐.

→ 의도 잠금 덕분에  
T2는 파일에 IX를 먼저 걸어야 하는데  
파일에 S가 이미 걸려 있으면 호환되지 않아!  
즉, 충돌을 적절히 처리할 수 있음.

---

# 📌 의도 잠금 호환성 테이블

(✔ = 호환됨, ✖ = 충돌)

||IS|IX|S|SIX|X|
|---|---|---|---|---|---|
|**IS**|✔|✔|✔|✔|✖|
|**IX**|✔|✔|✖|✖|✖|
|**S**|✔|✖|✔|✖|✖|
|**SIX**|✔|✖|✖|✖|✖|
|**X**|✖|✖|✖|✖|✖|

**해석 예시**

- IS vs IX → ✔ (둘 다 하위 노드만 다루기 때문에 괜찮음)
    
- S vs IX → ✖ (한쪽은 전체 읽기, 한쪽은 하위 수정 → 충돌)
    
- X vs anything → ✖ (X는 누구와도 안 어울림)
    

---

# 📌 의도 잠금의 핵심 역할 한 문장 요약

> 의도 잠금(IS, IX, SIX)은 “하위 노드에 어떤 잠금을 걸 것인지” 상위 노드에 미리 표시해,  
> 다중 계층 구조에서 효율적인 충돌 검사와 높은 동시성을 제공한다.
