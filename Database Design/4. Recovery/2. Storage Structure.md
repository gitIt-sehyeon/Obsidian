## 1. 저장 장치의 종류

### 🔹 Volatile Storage (휘발성 저장 장치)

- **시스템이 꺼지면(크래시/전원 차단) 내용이 사라지는 저장소**
    
- 예:
    
    - Main memory (주기억장치, RAM)
        
    - Cache memory (캐시 메모리)
        
- DB 입장에서는 **영구 저장용으로 쓸 수 없음** → 항상 디스크 등에 기록해야 함.
    

---

### 🔹 Nonvolatile Storage (비휘발성 저장 장치)

- **시스템 충돌 이후에도 데이터가 유지되는 저장소**
    
- 예:
    
    - Disk (하드디스크, SSD)
        
    - Tape (테이프)
        
    - Flash memory (플래시 메모리)
        
    - Battery-backed RAM (배터리 백업 RAM)
        
- 하지만:
    
    - 장치 자체가 고장나면(디스크 손상, 화재 등) **데이터가 날아갈 수 있음**
        

---

### 🔹 Stable Storage (안정 저장 장치)

- 이론상 개념:
    
    > **“어떠한 실패가 발생해도 데이터가 절대 사라지지 않는 저장소”**
    
- 현실에는 존재하지 않음 → **“신화적인 저장소(mythical storage)”**
    
- 대신, 다음 방식으로 **근사(approximate)** 한다:
    
    - 서로 다른 **비휘발성 매체에 여러 복사본을 저장**  
        (예: 디스크 2개, 심지어 물리적으로 다른 장소에 백업까지)
        

---

## 2. Stable Storage 구현 아이디어

### 🔹 기본 아이디어

- 각 데이터 블록을 **서로 다른 디스크에 여러 개의 복사본**으로 저장
    
- 재해(화재, 홍수, 디스크 고장 등)에 대비해서 **원격지에 백업**하기도 함
    

하지만 여전히 문제가 있음 👉 **전송 중 실패**

---

## 3. 데이터 전송 중 발생할 수 있는 실패 유형

메모리 ↔ 디스크 사이의 블록 전송 중에:

1. ✅ **성공적인 완료**
    
    - 둘 다 동일한 올바른 값 저장
        
2. ⚠️ **부분 실패 (Partial failure)**
    
    - 대상 블록이 **잘못된 정보**를 가지게 됨  
        (일부만 쓰이다가 실패)
        
3. ❌ **전체 실패 (Total failure)**
    
    - 대상 블록이 **아예 업데이트되지 않음**
        

⇒ 그래서 시스템은

> “전송 실패가 발생하면 이를 감지하고, 블록을 일관된 상태로 복구하는 절차”  
> 가 필요하다.

---

## 4. 쓰기(output) 연산을 안전하게 하는 한 가지 방법

**가정: 각 블록의 복사본이 디스크 2개에 있음**

출력(쓰기) 연산 절차:

1. 첫 번째 물리 블록에 데이터를 쓴다.
    
2. 첫 번째 쓰기가 **성공하면**, 두 번째 물리 블록에 동일한 데이터를 쓴다.
    
3. 두 번째 쓰기까지 **성공해야만** 최종적으로 “출력 완료”로 인정.
    

그래도 여전히,

- 두 번째 쓰기 도중 실패하면  
    → 두 복사본의 내용이 **달라질 수 있음** (inconsistent copies)
    

그래서 **복구 절차(recovery procedure)** 가 필요하다.

---

## 5. 전송 실패 후 복구 절차 (Stable-Storage Implementation)

### 1단계: 불일치(inconsistent) 블록 찾기

**방법 1 – 단순하지만 비싸다**

- 디스크의 모든 블록에 대해  
    두 복사본을 **모두 비교**한다.
    
- 디스크가 크면 굉장히 느림.
    

**방법 2 – 더 좋은 방법**

- “어떤 블록이 지금 쓰기 작업 중인지”를  
    소량의 **비휘발성 RAM(NVRAM)** 에 기록해둔다.
    
- 복구 시에는:
    
    - **쓰기 중이던 블록들만** 두 복사본을 비교하면 됨  
        → 비교해야 할 양이 크게 줄어듦.
        

---

### 2단계: 불일치 블록 복구

불일치하는 블록을 발견했을 때:

1. 두 복사본 중 **하나에 오류(체크섬 에러 등)가 있으면**  
    → **정상인 쪽으로 덮어쓴다** (정상본 → 손상본)
    
2. 두 복사본 모두 오류는 없지만 **내용이 서로 다르다면**  
    → 첫 번째 블록을 기준으로 정하고,  
    → **두 번째 블록을 첫 번째 블록 내용으로 덮어쓴다.**
    

이렇게 해서 두 복사본을 **동일하고 일관된 상태**로 복구한다.
