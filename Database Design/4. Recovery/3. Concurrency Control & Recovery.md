# Concurrency Control & Recovery 정리

## 1. 🔒 Concurrency Control 기본 개념

- 여러 트랜잭션이 **동시에 실행되면 같은 버퍼(buffer)와 로그(log)를 공유**한다.
    
- 하나의 버퍼 블록 안에 여러 트랜잭션이 수정한 데이터가 섞일 수 있다.
    
- **Strict 2PL(엄격한 2단계 로킹)** 가정:
    
    - 어떤 트랜잭션 Ti가 데이터 X를 수정하면 → **Ti가 commit 또는 abort하기 전까지 다른 트랜잭션은 그 X를 수정할 수 없음**
        
    - 즉, **Exclusive Lock을 끝까지 유지**한다.
        

---

## 2. 📝 로그(Log) 구조

트랜잭션 실행 중 다음 형태의 로그가 기록됨:

- `<Ti start>` : 트랜잭션 시작
    
- `<Ti, Xj, V1, V2>` : Ti가 Xj를 **V1(이전값)** 에서 **V2(새 값)**로 변경
    
- `<Ti commit>` : 커밋 완료
    

---

## 3. ↩️ 트랜잭션 롤백(Undo, 정상 작동 중)

Ti를 롤백해야 할 때 수행 절차:

1. **로그를 뒤에서부터 스캔**
    
2. `<Ti, Xj, V1, V2>` 를 만나면  
    → Xj에 **V1(이전 값)** 을 다시 기록 (Undo)  
    → Undo한 사실을 `<Ti, Xj, V1>` 형태로 **보상 로그(CLR)** 기록
    
3. `<Ti start>` 를 만나면  
    → `<Ti abort>` 기록하고 종료
    

---

## 4. 💥 장애 발생 시 Recovery (두 단계)

장애 후 복구는 **Redo → Undo 순서**로 진행된다.

---

## 4-1. 🔁 Redo Phase (history replay)

목표: 최근 checkpoint 이후의 **모든 트랜잭션의 변경을 재적용**  
(커밋 여부 상관없이 다 redo)

절차:

1. 마지막 `<checkpoint L>` 위치 찾기 → undo-list = L에 적힌 트랜잭션들
    
2. 체크포인트 이후부터 **앞으로 스캔**
    
    - `<Ti, Xj, V1, V2>` → Xj에 V2를 다시 기록 (redo)
        
    - `<Ti start>` 발견 → undo-list에 Ti 추가
        
    - `<Ti commit>` 또는 `<Ti abort>` → undo-list에서 제거
        

---

## 4-2. ⏪ Undo Phase (incomplete Tx 취소)

Redo 끝나면 **undo-list에는 미완료 트랜잭션만 남아있음**

Undo 절차:

1. 로그를 **뒤에서 앞으로 스캔**
    
2. `<Ti, Xj, V1, V2>` 발견 & Ti가 undo-list에 있으면
    
    - Xj ← V1 (Undo)
        
    - `<Ti, Xj, V1>` 보상 로그 기록
        
3. `<Ti start>` 발견 → `<Ti abort>` 기록 후 undo-list에서 제거
    
4. undo-list가 비면 종료
    

---

## 5. 💾 디스크(비휘발성 저장장치) 파괴 시 복구

- 주기적으로 DB 전체를 **dump**(백업)
    
- dump 시:
    
    - 메모리의 로그를 모두 저장
        
    - 버퍼의 모든 블록을 디스크로 flush
        
    - DB 전체를 stable storage로 복사
        
    - `<dump>` 로그 기록
        

### 복구 방법

1. 가장 최근 dump로 DB 복구
    
2. dump 이후 **commit된 트랜잭션만 redo**
    

---

## 6. 📌 전체 요약(시험용 핵심)

- **Strict 2PL**: 수정한 데이터에 대한 lock을 commit/abort까지 유지.
    
- **Recovery의 두 단계**
    
    - **Redo**: 체크포인트 이후 모든 기록 재적용 (history repeat)
        
    - **Undo**: 미완료 트랜잭션 rollback
        
- **Redo는 앞으로, Undo는 뒤로** 스캔
    
- **CLR(Compensation Log Record)**: Undo하면서 남기는 로그  
    → 장애가 또 나도 Undo 작업을 다시 반복할 수 있게 해준다.
    
- Dump는 디스크 손상 대비용 전체 백업
